# ATS 表单自适应填报与防截断策略（Anti-Truncation）

## 1. 行业内幕：为什么只上传附件 PDF 是不够的？

在主流企业招聘管理系统（ATS，如北森、飞书招聘、Moka、自建系统）中，候选人筛选链路包含两层过滤：
1. **第一层：结构化数据库初筛（SQL / 文本搜索过滤）**：
   HR 或业务线负责人在海量简历池中初筛时，后台系统通常优先基于候选人表单中的**结构化文本字段**（工作经历、项目职责、核心关键词）进行 ElasticSearch 关键字召回或算法自动评分。如果你的表单是空的，仅挂了一个 PDF 附件，你在第一层算法过滤中将严重失分！
2. **第二层：人工审阅 PDF 附件**：
   初筛通过后，面试官才会点击下载/预览 PDF 简历。

**结论：网页在线表单与 PDF 附件必须两手抓，且必须保持 100% 一致！**

## 2. 应对表单字符限制的自适应提炼

不同 ATS 输入框限制差异巨大（北森往往限制单条经历 300~500 字，飞书相对宽松）。直接粘贴整段简历会导致结尾的量化数据被截断。

### 自适应黄金结构（STAR 前置法则）
- **第 1 句（痛点与手段）**：`针对[业务难点]，基于[核心技术栈]设计[解决方案]...`
- **第 2 句（硬核成果）**：`[核心量化指标]，将性能提升XX%，保障零错账...`

把最具杀伤力的**动词、技术名词与量化数字始终放在前 100 个字内**，即使系统在 300 字处硬截断，初筛算法与 HR 也能在扫视第一眼时抓取到所有核心得分点。
